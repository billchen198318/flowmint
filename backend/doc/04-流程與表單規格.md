# 04 流程與表單規格

## 1. 流程生命週期

```text
DRAFT → PUBLISHED → RETIRED
```

- Draft 可編輯、驗證及預覽。
- Publish 產生不可變版本、SHA-256、Flowable deployment 與 task 設定快照。
- Published version 不可修改，只能複製成新 Draft。
- Retired version 不可新發起，但既有 instance 繼續執行。

發布檢查：

1. BPMN XML 可被 Flowable parse。
2. Process Key 與 FlowMint 主檔一致。
3. 每個 User Task 都有 Task Policy 與至少一條 Assignment Rule。
4. Resolver 設定 JSON 符合對應 schema。
5. 每個 User Task 僅配置一張表單，且引用的表單版本已發布。
6. 所有 gateway expression 只使用允許的表單變數。
7. 無任意 Groovy、Java class 或 Script Task。

## 2. 首版 BPMN 範圍

允許：

- Start／End Event。
- User Task。
- Service Task 白名單。
- Exclusive／Parallel Gateway。
- Timer Boundary Event。
- Call Activity 延後至第二階段。

禁止使用可執行任意程式的 Script Task、未註冊 Delegate Expression、直接 SQL 及任意 HTTP。

## 3. 表單

Form Version 保存：

- JSON Schema：型別、必填、格式與驗證。
- UI Schema：元件、排列與顯示。
- SHA-256：確認發布內容不被修改。

Runtime 只接受 Schema 定義過的欄位；server-side 必須重新驗證，不能只信任前端。

## 4. 欄位權限

每個 User Task 的 `FIELD_POLICY` 明確定義：

每個 User Task 僅能綁定一張表單版本。綁定關係以 Tenant、流程定義、流程版本及 `TASK_DEF_KEY` 唯一識別；同一 User Task 不允許新增第二筆表單設定。切換表單時應更新既有 `fm_task_form_rule`，不得以新增資料方式保留多張表單。

```json
{
  "default": "READ",
  "fields": {
    "amount": "READ",
    "financeComment": "EDIT",
    "internalScore": "HIDDEN"
  }
}
```

允許值為 `HIDDEN`、`READ`、`EDIT`。必填規則仍由 server 合併 Form Schema 與 Task 規則驗證。

## 5. 申請單狀態

```text
DRAFT
  → SUBMITTED
  → RETURNED → SUBMITTED
  → COMPLETED
  → REJECTED
  → CANCELLED
```

- 只有 Owner 可修改 Draft／Returned。
- Submitted 內容不得原地修改。
- 每次 Submit、Resubmit 及 Task Action 建立 immutable snapshot。
- 使用 `LOCK_VERSION` optimistic locking。

## 6. Task Action

首版支援：

- Submit／Resubmit。
- Approve。
- Reject，理由必填。
- Return，理由與目標必填。
- Withdraw：僅流程未被他人處理前。
- Cancel：依流程政策。
- Transfer：保留 From/To/Reason。
- Delegate／Resolve。
- Add Sign。
- Admin Reassign／Terminate。

所有動作驗證登入 Actor、任務所有權、Task Policy、表單狀態及 Flowable 狀態。

## 7. 快照

每次有效動作保存：

- 完整表單 JSON 與 SHA-256。
- 表單版本與 revision。
- Assignment Resolver 輸入、路徑及結果。
- Actor、Principal、代理與轉派關係。
- Task、Process Instance 及時間。

快照只 Insert，不 Update、不 Delete。
## 8. FM_PROG004D0001 完整流程設計與版本

流程主檔以 `PROCESS_DEF_ID` 作為穩定識別，Tenant 與 `PROCESS_KEY` 建立後不可修改。新增主檔時自動建立第 1 版草稿；草稿可由 bpmn-js 編輯並反覆儲存。若已有草稿，不得重複建立另一份草稿。

在 bpmn-js 選取 User Task 時，節點屬性面板必須提供單一表單選擇欄位，只能選擇同 Tenant 已發布的表單版本。選擇結果寫入 `fm_task_form_rule`；每個 User Task 只能存在一筆表單綁定。使用者改選其他表單時更新原綁定，清除選擇時刪除原綁定。流程發布時，任何 User Task 未綁定表單、綁定多張表單或引用未發布表單，都必須阻擋發布並指出節點。

`FM_PROG004D0001` 是流程設計的唯一使用者操作入口。使用者在 bpmn-js 點選 User Task 後，必須直接在同一個右側節點屬性面板完成下列設定，不得要求使用者離開流程設計器，再以流程版本與節點代碼到另一支 CRUD 程式設定：

- 節點顯示的單一 Form 與 Form Version。
- Task Policy：Approve、Reject、Return、Transfer、Delegate、Add Sign 等允許動作。
- Assignment Rule／Resolver：部門主管、直屬主管、上層部門主管、組織職稱、簽核群組、指定人員或受控流程變數。
- Resolver 所需參數、多人簽核模式、找不到簽核人時的處理方式、代理與逾時政策。
- 使用與 Runtime 相同解析邏輯的 Resolver Preview，顯示解析步驟、實際簽核人及略過原因。

儲存流程草稿時，BPMN XML、Form 綁定、Task Policy 與 Assignment Rule 必須在同一個後端交易中一起驗證及保存。簽核人規則存放於 FlowMint 結構化資料表，不把實際人員直接寫死於 BPMN XML，也不允許使用者手寫 Resolver JSON。

發布時必須確認 BPMN 只有一個 Process，且 Process ID 等於主檔 `PROCESS_KEY`，再由 Flowable parser 驗證並部署。成功後回寫 BPMN SHA-256、Flowable Deployment ID、Process Definition ID、發布者與發布時間。已發布版本不可修改；發布新版本時，上一個已發布版本改為 `RETIRED`，既有流程實例仍依原部署執行。

發布動作同樣由 `FM_PROG004D0001` 執行。發布前以清楚的 validation report 一次列出 BPMN、Form、Task Policy、Assignment Rule、核決權限條件、Resolver Preview 與 Gateway 條件錯誤；全部通過後才可部署。`FM_PROG004D0002` 不再作為獨立使用者程式、選單或 CRUD 頁面，其原訂的 Task Policy／Resolver 能力併入 `FM_PROG004D0001` 的 User Task 節點屬性面板。`FM_PROG004D0003` 原訂的 Resolver Preview／發布檢查，以及原 `FM_PROG004D0004` 的核決權限與條件規則，也都作為 `FM_PROG004D0001` 的內嵌能力，不建立其他操作入口。

## 9. FM_PROG005D0001 客製 JavaScript

Form Version 除 Form.io Schema 與 UI Schema 外，另以 fm_form_version.CUSTOM_SCRIPT_CONTENT 保存表單級客製 JavaScript。欄位型別為 MariaDB LONGTEXT，既有環境使用 FM_PROG005D0001-custom-script-schema.sql 增加欄位。

客製 JavaScript 與表單版本具有相同生命週期：

- Draft 可編輯、檢查及試跑。
- 建立新版本時複製上一版 Script。
- Published／Retired 版本不可修改。
- 發布內容 SHA-256 依序包含正規化後的 SCHEMA_CONTENT、UI_SCHEMA_CONTENT 與 CUSTOM_SCRIPT_CONTENT，三段內容以 LF 分隔。
- Script 換行在後端保存前正規化為 LF；空值正規化為空字串。

第一版表單級 Script 使用單一回傳物件，支援 onFormLoad、onFieldChange、beforeSubmit、afterSubmit、onDataActionSuccess、onDataActionError 與 onDestroy。Designer Preview 與未來正式 Runtime 必須共用相同 Executor 及 Context 契約，詳細內容見 [FM_PROG005D0001 客製 JavaScript 規劃說明](FM_PROG005D0001_cust_js規劃說明.md)。
