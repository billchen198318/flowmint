# FlowMint AI 簽核解說精靈規劃

## 1. 文件狀態

本文件定義 FlowMint Runtime「AI 簽核解說精靈」的產品、資料、安全、API、Provider 與驗收契約。目前僅完成規劃，尚未建立資料表、Java、Vue 或正式 Provider 連線，不得標示為已實作或已上線。

第一版支援 OpenAI GPT、Google Gemini、Groq 與 OpenRouter，並保留未來接入 Ollama、vLLM 或其他 OpenAI-compatible Provider 的擴充點。

## 2. 目標與邊界

AI 解說精靈只出現在正式表單 Runtime 的目前待辦頁。合法簽核者點擊後，後端以目前表單 Revision、流程資訊及既有 Task Action 意見建立受控 Context，呼叫 Tenant 指定的 AI Provider，回傳案件摘要、重要事實、風險、待確認問題及參考建議，協助簽核者快速理解案件。

AI 不得：

- 自動核准、駁回、退回、轉派、加簽或完成 Flowable Task。
- 自動修改表單資料、流程變數、Task Policy、Resolver 或核決權限。
- 將 AI 產生內容寫成簽核者意見或冒用簽核者身分。
- 將建議直接映射為可自動執行的簽核動作。
- 在表單設計器 Preview、未授權申請追蹤頁或非 active Task 中執行。

AI 結果一律顯示「僅供參考，最終決策與責任仍屬簽核者」。

## 3. Runtime 流程

```text
簽核者開啟 active Task
→ 點擊「AI 解說精靈」
→ 後端重新驗證 Tenant、Task、流程與操作者資格
→ 回傳該 Tenant 的有效 Provider／Model，由簽核者選擇
→ 讀取發布表單 Schema、目前表單資料與歷史 Task Action
→ 依系統共通安全規則過濾、標籤化、遮罩與限制資料量
→ 計算 Content Hash，優先回用相同分析
→ 解密 Provider API Key 並呼叫模型
→ 驗證結構化回應
→ 保存分析稽核與用量
→ 前端呈現摘要、風險、問題與參考建議
```

## 4. AI Provider 管理

新增 Tenant-scoped 管理功能，暫定程式代碼 `FM_PROG010D0001`，供授權管理員建立、測試、停用及指定使用者選單的預選 Provider。

Provider 設定至少包含：

| 欄位 | 說明 |
|---|---|
| `PROVIDER_CODE` | Tenant 內唯一代碼 |
| `PROVIDER_TYPE` | `OPENAI`、`GEMINI`、`GROQ`、`OPENROUTER` |
| `DISPLAY_NAME` | 管理與 Runtime 顯示名稱 |
| `BASE_URL` | 官方端點或受控相容端點 |
| `MODEL_ID` | 實際模型代碼，不使用模糊顯示名稱代替 |
| `API_KEY_CONTENT` | AES-GCM 加密後的 API key |
| `TEMPERATURE` | 第一版預設 `0.2` |
| `MAX_OUTPUT_TOKENS` | 單次輸出上限 |
| `TIMEOUT_SECONDS` | 建議限制 30 至 60 秒 |
| `DEFAULT_FLAG` | 使用者選單的預選 Provider，不限制使用者改選其他有效項目 |
| `CONFIG_VERSION` | 設定變更版本，納入 Content Hash |
| `STATUS` | `ACTIVE`／`INACTIVE` |
| `LAST_TEST_STATUS` | 最近連線測試結果 |
| `LAST_TEST_DATE` | 最近測試時間 |

API key 安全契約：

- 使用獨立的 `fm.ai.encryption-key`，不得與資料來源密碼、JWT 或其他功能共用金鑰。
- 明文只允許在儲存及實際呼叫期間存在於後端記憶體，不得進入 Log、Exception、DTO、前端 Store、Task Action 或分析結果。
- Load API 永不回傳明文，只回傳遮罩，例如 `****abcd`。
- Edit 未輸入新 key 時保留原密文；不得將遮罩字串覆寫成新 key。
- 測試連線必須使用最小請求，並清理 Provider 原始錯誤中的 Header、URL query 與憑證。
- `BASE_URL` 依 Provider 使用 allowlist 或受控管理權限，防止利用後端執行 SSRF。

## 5. 全域使用規則

AI 解說精靈不在 BPMN、流程版本或 User Task 節點配置，也不建立流程級 `AI Policy`。所有正式 active 簽核 Task 的表單一律顯示「AI 解說精靈」按鈕；是否呼叫完全由目前簽核者當下決定。

簽核者點擊按鈕後，Runtime 列出該 Tenant 在 `FM_PROG010D0001 AI Provider 管理` 建立的所有有效 Provider／Model，由簽核者選擇本次要使用的項目。`DEFAULT_FLAG` 只控制畫面預選值，不強制使用；若只有一個有效項目則直接預選。若目前 Tenant 沒有任何有效 Provider，按鈕仍固定顯示；點擊後不得呼叫任何外部服務或建立分析紀錄，前端必須顯示：「目前尚未設定 AI API，請聯絡系統管理員至 AI Provider 管理新增並啟用設定。」此狀況不得影響正常簽核。

所有流程共用固定的後端安全規則：

- 固定包含目前表單內容與先前 User Task 的簽核 Comment／Reason。
- 依 Form.io Schema 轉換欄位標題與值，不需要在 BPMN 逐欄設定。
- 固定排除 Password、技術欄位、憑證、Custom Script、SQL 及其他 Tenant 資料。
- 第一版不傳送附件內容，只提供已授權的檔名等 metadata。
- 統一執行個資遮罩、歷史筆數、輸入長度、輸出語言與 Token 上限。
- 單一 Task、使用者及 Tenant 仍須有頻率與每日額度防線。

上述規則屬 AI Runtime 的系統契約，由程式與 Tenant Provider 設定管理，不與流程發布版本綁定。

## 6. 資料模型

### 6.1 `fm_ai_provider`

保存 Provider、模型、端點、加密 API key、限制、狀態及測試結果。Tenant 與 Provider Code 必須唯一；同 Tenant 同時最多一筆有效預選 Provider。未設定預選值時，前端以 Provider Code 排序後第一筆作為初始選項，但使用者仍可改選。

### 6.2 `fm_ai_analysis`

保存每次分析的不可變稽核資料：

- Tenant、Process Instance ID、Task ID、Task Definition Key。
- Form Data ID、Form Revision。
- Actor Account。
- Provider Code、Provider Type、Model ID、Config Version。
- Prompt Template Version、Content Hash、Generation No。
- 執行狀態、錯誤碼、開始／完成時間及耗時。
- Input／Output Token 或 Provider 回傳的等價用量。
- 結構化分析結果。
- 是否由 force refresh 產生。

預設不保存完整 Prompt 及未遮罩表單資料，只保存 Content Hash 與結構化結果。若 Tenant 法遵要求保存完整輸入，必須以獨立資料治理設定、加密欄位及保留期限實作。

同一 Tenant 與 Content Hash 可以有多個 Generation；一般請求回用最新成功 Generation，`forceRefresh` 建立下一個 Generation。資料庫唯一鍵使用 Tenant、Content Hash、Generation No，不以 Content Hash 單獨阻止合法刷新。

### 6.3 `fm_ai_analysis_access`

每次點擊、快取命中、開始分析、失敗或讀取既有結果都建立獨立存取稽核，至少保存 Tenant、Analysis ID、Task ID、Actor Account、Access Type、Request Date、Result Status 與錯誤碼。分析內容只保存於 `fm_ai_analysis`，Access 紀錄以外鍵引用，不複製模型輸出。

此拆分確保同一分析可安全提供給多名合法 candidate，同時保留每位使用者的存取事實；不得為記錄第二位使用者而修改第一筆不可變分析的 Actor。`fm_ai_analysis` 的 Actor 表示實際觸發該次 Provider 呼叫的人，快取讀取者記錄於 `fm_ai_analysis_access`。

## 7. AI Context Builder

所有模型輸入由後端建立。前端只可提交從後端 options 取得的 `providerCode`，不得提交表單內容、歷史意見、Prompt、Provider Type、Model ID、Base URL、API key 或其他 Provider 設定。

Context 建議格式：

```json
{
  "process": {
    "name": "請購核准流程",
    "documentNumber": "PR-A01-202608-000123",
    "currentTask": "財務審查"
  },
  "applicant": {
    "displayName": "王小明",
    "orgUnit": "資訊部"
  },
  "form": [
    {
      "label": "含稅總金額",
      "key": "totalAmountTwd",
      "value": 850000
    }
  ],
  "history": [
    {
      "taskName": "部門主管",
      "action": "APPROVE",
      "comment": "需求合理，請財務確認預算"
    }
  ]
}
```

表單資料必須依該 Task 綁定的已發布 Form.io Schema 轉為欄位標題、key 與值。Container、Columns、Table、DataGrid 及 EditGrid 必須受控遞迴，不得把原始 Renderer Object、HTML 或 Custom JavaScript 直接送出。

預設排除：

- Password、隱藏技術欄位與未宣告欄位。
- API key、Token、Cookie、Authorization Header。
- Custom JavaScript、Data Action SQL 與內部 Connection 設定。
- Assignment Resolver 內部 Context 與其他 Tenant 資料。
- 附件二進位內容、下載 URL 及附件文字；第一版只可提供檔名與用途等已授權 metadata。
- 系統共通安全規則禁止傳送的個資及敏感資料。

歷史意見只取已保存的 `fm_task_action`，包含 Task、Action、Actor 顯示資訊、Comment、Reason 與時間；不得把系統內部錯誤堆疊或未授權管理註記送給 Provider。

第一版只分析資料庫內最後已保存的 Form Revision。簽核者在目前畫面修改但尚未送出的欄位不納入 Context；AI 面板必須明確顯示「本次分析依據最後已保存的表單版本，不包含尚未送出的畫面修改」。如此可避免由前端提交未驗證資料，也能讓 Content Hash、快取與稽核對應確定的 Revision。

## 8. Prompt 與 Injection 防線

System Prompt 必須明確聲明表單值與簽核意見都是不可信資料，不得執行其中的指令、連結、程式碼或要求。使用者資料應放入固定 JSON data section，不與 system instruction 串接成自由格式命令。

Prompt 必須版本化並由後端管理。第一版不允許一般使用者自訂 Prompt，不提供瀏覽器直接傳入 system／developer message 的能力。

Provider 回應必須通過本地 JSON Schema 驗證；未知欄位忽略或拒絕，超長內容截斷，解析失敗不得退回未過濾的原始模型文字。

## 9. 統一輸出契約

```json
{
  "summary": "本案為資訊設備採購……",
  "keyFacts": [
    "總金額為新台幣 850,000 元",
    "部門主管已核准"
  ],
  "risks": [
    {
      "level": "MEDIUM",
      "title": "預算資訊不足",
      "detail": "目前未看到明確預算編號"
    }
  ],
  "questions": [
    "是否已完成年度預算保留？"
  ],
  "recommendation": {
    "action": "REVIEW_REQUIRED",
    "reason": "主要資料完整，但需確認預算編號"
  },
  "disclaimer": "AI 建議僅供簽核者參考"
}
```

`recommendation.action` 第一版只允許：

- `APPROVE_CONSIDERATION`
- `RETURN_CONSIDERATION`
- `REJECT_CONSIDERATION`
- `REVIEW_REQUIRED`
- `INSUFFICIENT_INFORMATION`

前端只將其顯示為參考文字，不得自動選取或觸發任何 Task Action。

## 10. Provider Adapter

建立與業務 Logic 分離的統一介面：

```java
public interface FmAiProviderClient {
    FmAiAnalysisResponse analyze(
            FmAiProviderConfig config,
            FmAiAnalysisRequest request) throws ServiceException;
}
```

第一版實作：

- `FmOpenAiProviderClient`
- `FmGeminiProviderClient`
- `FmGroqProviderClient`
- `FmOpenRouterProviderClient`

OpenAI、Groq 與 OpenRouter 可共用 OpenAI-compatible HTTP 基礎實作，但仍須各自維護 endpoint、model、錯誤碼與用量 mapper；Gemini 使用獨立 request／response mapper。業務 Logic 不得直接判斷各 Provider 的 JSON 結構。

所有 HTTP Client 必須設定 connect、request、read timeout、response size limit、TLS 驗證及受控 retry。只有可判定為 transient 且尚未收到有效模型結果的錯誤才可重試；不得對 authentication、quota、validation 或 policy 錯誤重試。

## 11. Runtime API

```text
POST /api/fm/tasks/ai-provider-options
POST /api/fm/tasks/ai-analysis
GET  /api/fm/tasks/ai-analysis/{analysisId}
```

`ai-provider-options` 只回傳目前 Tenant 的有效 `providerCode`、顯示名稱、Provider Type 與 Model ID，不回傳 Base URL、API key、遮罩 key 或其他連線設定。

Provider options Request：

```json
{
  "taskId": "..."
}
```

Provider options 與 analysis 使用相同的 active Task、Tenant、流程狀態及操作者資格驗證；不得只因使用者具有 Tenant membership 就列出 Provider。一般 Flowable Task 及平行加簽 standalone subtask 必須分別沿用其正式 Runtime 授權鏈路。

Request 僅接受：

```json
{
  "taskId": "...",
  "providerCode": "COMPANY_GEMINI",
  "forceRefresh": false
}
```

前端只可從後端 options 選擇 `providerCode`，不得指定 Tenant、Actor、Form Data、歷史意見、Prompt、Provider API key、Base URL 或 Model ID。後端必須以 Security Context 的 Tenant 重新查詢該 Provider Code，不能相信前端夾帶的 Provider 屬性。

呼叫前必須重新驗證：

1. 登入者具有目前 Tenant membership。
2. Task 仍存在且流程為 `RUNNING`。
3. 登入者是 Task assignee，或是尚未 claim 的合法 candidate。
4. Task 是正式簽核節點或平行加簽的 active standalone subtask；申請人補件及其他非簽核用途 Task 不適用。
5. 使用者選擇的 Provider Code 屬於目前 Tenant，且 Provider 啟用、設定完整、API key 可解密。
6. 表單、歷史 Action 與流程資料都屬於相同 Tenant／Process Instance。
7. 呼叫頻率、並發與 Tenant 額度未超限。

Task 已完成、已改派而失去權限、流程已撤回／駁回／終止，或使用者只因過去曾參與流程而可查看歷程時，均不得建立新分析。

## 12. 快取、冪等與費用控制

Content Hash 至少包含：

```text
Tenant
+ Process Instance ID
+ Task ID
+ Form Revision
+ Action History Hash
+ Provider Config Version
+ Prompt Template Version
```

相同 Content Hash 的一般請求回傳最新成功 Generation，不重複呼叫 Provider；每次快取命中仍新增 `fm_ai_analysis_access`。表單 Revision、歷史 Action、Provider Config 或 Prompt 版本改變時會形成新的 Content Hash。

`forceRefresh=true` 保留相同 Content Hash，但以原子方式取得下一個 Generation No 並建立新分析，不受 Content Hash 單獨唯一限制。資料庫以 Tenant、Content Hash、Generation No 唯一；後端對同一 Content Hash 加鎖或使用 pending 唯一防線，避免雙擊或多分頁同時產生兩筆相同 Generation 的外部請求。`forceRefresh` 仍須受到冷卻時間與每日額度限制。

## 13. 前端 Runtime UX

在 `frontend-v-nx/pages/tasks/[id].vue` 的所有正式簽核待辦詳情固定加入「AI 解說精靈」按鈕，不需 BPMN 或節點設定。簽核者不點擊時不呼叫 Provider，也不產生費用；點擊後先開啟 Provider／Model 選擇畫面，確認後才由後端重新驗證權限並執行分析。未設定任何有效 Provider 時，按鈕仍可點擊，但只顯示「目前尚未設定 AI API，請聯絡系統管理員至 AI Provider 管理新增並啟用設定。」不得送出分析 Request，也不得阻擋原簽核功能。

建議以側邊面板或 Modal 顯示：

- 本次使用的 Provider／Model 選項；只列 Tenant 有效設定，不顯示 API key 或 Base URL。
- 案件摘要。
- 重要資料。
- 歷史簽核意見整理。
- 風險與異常。
- 建議確認問題。
- AI 參考建議。
- Provider／Model、產生時間、表單 Revision。
- 是否為快取結果。
- 「重新分析」按鈕與冷卻提示。
- 「本次分析依據最後已保存的表單版本，不包含尚未送出的畫面修改」提示。
- 固定免責聲明。

AI 失敗不得阻擋正常簽核。Timeout、Quota、Provider unavailable 或輸出格式錯誤時，顯示可理解的錯誤與重試條件，不顯示 API key、完整 Prompt、Stack Trace 或 Provider 原始敏感回應。

## 14. 權限、稽核與資料治理

- Provider 管理使用獨立管理權限；不建立 BPMN AI Policy 管理權限。
- AI 分析權限不因能查看流程圖、申請追蹤或歷史 Action 而自動取得。
- 每次實際 Provider 呼叫保存於 `fm_ai_analysis`；每次成功、失敗、快取命中、強制刷新及結果讀取另保存 `fm_ai_analysis_access`，完整記錄 Actor 與 Task。
- API key 新增、輪替、停用及連線測試必須保存管理稽核，但不保存明文。
- 正式上線前必須完成個資、機密資料、跨境傳輸、Provider 資料保留及模型訓練政策確認。
- AI 結果需有保留期限；流程與稽核依法需永久保存時，也不代表完整 Prompt 必須永久保存。

## 15. 測試與驗收

### 15.1 Provider 與密鑰

- 四種 Provider 的 request／response mapper 契約測試。
- API key AES-GCM 加解密、遮罩、輪替及空白保留測試。
- API key 不出現在 DTO、Log、Exception、稽核內容及前端網路回應。
- Base URL allowlist、TLS、timeout、response size 及 SSRF 防線。

### 15.2 權限與 Tenant

- Assignee、合法 candidate 可分析；無關人員、已改派原人員及只有歷史查看權者拒絕。
- 平行加簽 active standalone subtask 的合法成員可分析；其他成員、批次發起人及母 Task 處理人不能以該 subtask ID 越權分析。
- Task 完成、流程撤回／駁回／終止後拒絕新分析。
- Body 無法覆寫 Tenant、Actor、Provider、Model、Prompt 或表單資料。
- 不得讀取其他 Tenant 的 Provider、表單、Action 或分析結果。
- Tenant 沒有任何有效 Provider 時，按鈕仍顯示；點擊只顯示聯絡管理員新增 AI API 設定的固定訊息，且 Provider options 為空、外部呼叫次數與 `fm_ai_analysis` 新增筆數皆為零。

### 15.3 Context 與輸出

- 一般欄位、Container、Columns、Table、DataGrid、EditGrid 正確標籤化。
- Password、隱藏技術欄位、Custom Script、SQL、Token 及禁止欄位確實排除。
- 歷史 Comment／Reason 排序、筆數與長度限制正確。
- 表單或意見內的 Prompt Injection 不會覆寫 system instruction。
- 非 JSON、缺欄位、未知 action、超長回應與惡意 HTML 被拒絕或安全處理。

### 15.4 快取與費用

- 相同 Content Hash 的一般請求不重複呼叫 Provider，但每次快取使用都新增 Access 稽核。
- Form Revision、Action History、Provider Config 或 Prompt 版本改變會產生新 Content Hash。
- `forceRefresh` 在相同 Content Hash 下建立下一個 Generation，且不違反資料庫唯一鍵。
- 雙擊、併發與相同 request 不會重複計費。
- force refresh、每人／Task／Tenant 限流與每日額度正確。

### 15.5 瀏覽器 E2E

- 四種 Provider 至少各完成一次真實連線驗收。
- 同一 Task 分別選擇 Gemini、GPT、Groq、OpenRouter 時，只能使用該 Tenant 的有效設定，且各自產生獨立 Content Hash 與分析紀錄。
- 使用不同 assignee／candidate／無權限帳號驗證按鈕與 API。
- 表單修改或新增簽核意見後重新分析，Revision 與內容更新正確。
- 畫面尚未送出的欄位修改不進入 AI Context，且面板清楚顯示最後已保存 Revision 提示。
- Provider timeout 或 quota exhausted 時仍可正常完成簽核。
- AI 建議不會自動選取或提交 Approve／Return／Reject。

## 16. 實作順序

1. `fm_ai_provider`、密鑰加密、管理 API 與管理畫面。
2. Provider Adapter、受控 HTTP Client 與測試連線。
3. 表單／Task Action Context Builder 與共通遮罩規則。
4. Prompt Template、Structured Output Schema 與回應驗證。
5. `fm_ai_analysis`、`fm_ai_analysis_access`、Content Hash、Generation、冪等、限流與用量稽核。
6. Task Runtime 權限 API。
7. 所有正式簽核表單共用的 AI 解說精靈前端面板。
8. Provider 契約測試、資安測試及瀏覽器多帳號 E2E。

第一版只處理結構化表單文字與既有簽核意見，不解析附件內容，也不允許 AI 自動執行任何流程動作。完成所有 Provider、權限、資料遮罩、輸出驗證與多帳號 E2E 前，不得標示為正式上線。
