# 37 部門人員與主管配置操作說明

日期：2026-09-22  
適用對象：組織資料管理員、IT 管理人員、FlowMint 管理員

## 1. 文件目的

本文件說明如何在 FlowMint 建立部門、人員任職、部門主管與員工直屬主管，使簽核流程能正確解析主管。

相關程式：

| 程式 | 用途 |
|---|---|
| `FM_PROG002D0001` | 員工資料、主要／兼任部門，以及該員工每筆任職的直屬主管來源 |
| `FM_PROG002D0002` | 部門資料及上下層組織樹 |
| `FM_PROG002D0004` | Tenant 共用職稱與簽核 Level |
| `FM_PROG002D0005` | 各部門的主要主管、副主管及代理主管 |
| `FM_PROG002D0007Q` | 完成配置後檢查組織、人員、主管及代理資料 |

最重要的觀念：

> 員工在某部門任職，不代表該員工是該部門主管；員工自己的直屬主管，也不等於他所管理的部門。

## 2. 建議配置順序

請依下列順序配置，避免後續畫面沒有可選資料：

1. 在「組織職稱（`FM_PROG002D0004`）」建立會使用的職稱。
2. 在「部門與組織樹（`FM_PROG002D0002`）」建立最高部門及下級部門。
3. 在「員工與任職（`FM_PROG002D0001`）」建立員工及其部門任職。
4. 在「部門主管與代理主管（`FM_PROG002D0005`）」配置各部門主管。
5. 回到「員工與任職（`FM_PROG002D0001`）」確認每筆任職的直屬主管來源。
6. 在「組織人員資料檢查（`FM_PROG002D0007Q`）」執行檢查。

## 3. 建立最高部門與組織樹

在「部門與組織樹（`FM_PROG002D0002`）」建立部門時：

- 每個 Tenant 同一時間只能有一個最高部門。
- 最高部門的「上級部門」留空。
- 其他部門必須選擇有效的上級部門。
- 不得把部門本身或其下級部門設為上級部門。
- 部門狀態與生效期間必須涵蓋實際使用時間。

範例：

```text
00001／阿成金屬工業       上級部門：留空
└─ 00002／董事長室        上級部門：00001／阿成金屬工業
   ├─ 00100／管理部       上級部門：00002／董事長室
   └─ 00200／製造部       上級部門：00002／董事長室
```

最高部門可以沒有上級部門，但不會因此自動擁有部門主管。

## 4. 建立員工與部門任職

在「員工與任職（`FM_PROG002D0001`）」建立或編輯員工後，於「部門任職與直屬主管」區塊新增任職：

1. 選擇「部門」。
2. 選擇「職稱」。
3. 選擇「直屬主管來源」。
4. 設定是否為「主要任職」。
5. 設定狀態及生效／失效時間。
6. 按「新增任職」或「更新任職」。

同一員工可以在多個部門任職，但相同時間只能有一筆主要任職：

| 任職 | `IS_PRIMARY` |
|---|---|
| 主要所屬部門 | `Y` |
| 兼任的其他部門 | `N` |

例如陳建宏同時任職於阿成金屬工業與董事長室，可以配置兩筆任職，但只能選一筆為「主要任職」。

## 5. 配置部門主管

部門主管必須在「部門主管與代理主管（`FM_PROG002D0005`）」配置。操作前，主管人選必須已在該部門具有有效任職，否則不會出現在候選名單。

操作步驟：

1. 進入「部門主管與代理主管（`FM_PROG002D0005`）」。
2. 選擇 Tenant 與部門。
3. 選擇該部門具有有效任職的員工。
4. 選擇主管類型。
5. 設定優先序、狀態及生效／失效時間。
6. 儲存後確認清單中的部門、人員與期間正確。

主管類型：

| 畫面名稱 | 保存值 | 用途 |
|---|---|---|
| 主要主管 | `HEAD` | 流程解析「本部門主管」時使用；同一部門同一時間應只有一位 |
| 副主管 | `DEPUTY_HEAD` | 協助管理；不取代正式主要主管 |
| 代理主管 | `ACTING_HEAD` | 主管暫時無法處理時使用，應設定明確代理期間 |

只有副主管或代理主管，仍不代表部門已配置正式主要主管。

### 5.1 同一人管理多個部門

同一員工可以同時擔任多個部門主管，但必須：

- 在每個部門各有一筆有效任職。
- 在「部門主管與代理主管（`FM_PROG002D0005`）」對每個部門各建立一筆主要主管（`HEAD`）。

例如陳建宏同時管理兩個部門，需要兩筆主管配置：

```text
00001／阿成金屬工業 → FM00002／陳建宏 → 主要主管
00002／董事長室     → FM00002／陳建宏 → 主要主管
```

只在「員工與任職（`FM_PROG002D0001`）」建立兩筆任職，不會自動產生上述主管配置。

## 6. 選擇員工直屬主管來源

「直屬主管來源」是設定該員工在這筆任職中向誰報告，而不是把該員工設為部門主管。

| 畫面選項 | 保存值 | 使用時機 |
|---|---|---|
| 本部門主管 | `ORG_HEAD` | 直屬主管是自己任職部門的主要主管 |
| 上層部門主管 | `PARENT_HEAD` | 直屬主管是上級部門的主要主管，常用於部門主管本人 |
| 指定員工任職 | `EXPLICIT` | 實際匯報關係不依組織樹，需指定某人的特定有效任職 |
| 不設定直屬主管 | `NONE` | 最高負責人或經核准確實沒有主管的例外 |

選擇原則：

- 一般員工通常使用「本部門主管」。
- 部門主管通常使用「上層部門主管」。
- 矩陣式或特殊匯報關係使用「指定員工任職」。
- 最高負責人使用「不設定直屬主管」。
- 最高部門沒有上級部門，因此最高部門任職若使用「上層部門主管」，一定無法找到主管。

## 7. 最高部門與最高負責人完整範例

假設：

- `00001／阿成金屬工業` 是唯一最高部門。
- `00002／董事長室` 是其下級部門。
- `FM00002／陳建宏` 是最高負責人，並同時管理兩個部門。

正確配置如下：

### 7.1 組織部門

在「部門與組織樹（`FM_PROG002D0002`）」：

| 部門 | 上級部門 |
|---|---|
| `00001／阿成金屬工業` | 留空 |
| `00002／董事長室` | `00001／阿成金屬工業` |

### 7.2 人員任職與本人主管

在「員工與任職（`FM_PROG002D0001`）」：

| 員工 | 任職部門 | 主要任職 | 直屬主管來源 |
|---|---|---|---|
| 陳建宏（FM00002） | 00001／阿成金屬工業 | 否 | 不設定直屬主管 |
| 陳建宏（FM00002） | 00002／董事長室 | 是 | 不設定直屬主管 |

若企業規則只允許最高負責人的主要任職使用 `NONE`，另一筆兼任任職應依實際匯報關係改用 `ORG_HEAD` 或 `EXPLICIT`；不得為了消除警告而任意設定。

### 7.3 部門主管

在「部門主管與代理主管（`FM_PROG002D0005`）」：

| 部門 | 主管 | 類型 |
|---|---|---|
| 00001／阿成金屬工業 | 陳建宏（FM00002） | 主要主管 |
| 00002／董事長室 | 陳建宏（FM00002） | 主要主管 |

完成後，陳建宏同時是兩個部門的主管，但他本人的兩筆任職沒有直屬主管；兩種資料並不衝突。

## 8. 完成後檢查

進入「組織人員資料檢查（`FM_PROG002D0007Q`）」，選擇 Tenant 並重新檢查下列四區：

1. 部門主管問題。
2. 員工直屬主管問題。
3. 上級部門與組織樹問題。
4. 工作代理問題。

若仍有問題，依畫面顯示的姓名／員編、部門代碼／名稱、判定依據及建議處理，回到對應維護程式調整。此檢查頁不會自動修改正式資料。

## 9. 常見問題

| 畫面訊息或現象 | 常見原因 | 處理方式 |
|---|---|---|
| 未配置部門主管 | 只有員工任職，沒有該部門的有效主要主管（`HEAD`） | 到「部門主管與代理主管（`FM_PROG002D0005`）」配置主要主管 |
| 主管人選沒有出現在候選名單 | 該員工沒有該部門的有效任職 | 先到「員工與任職（`FM_PROG002D0001`）」建立任職 |
| 最高負責人未配置有效直屬主管 | 其任職仍使用 `ORG_HEAD`、`PARENT_HEAD` 或無效的 `EXPLICIT` | 若確實沒有主管，改選「不設定直屬主管」 |
| 最高部門使用上層部門主管仍找不到人 | 最高部門沒有上級部門 | 最高負責人使用 `NONE`；若仍需報告給某人，使用 `EXPLICIT` |
| 同一人管理兩個部門，但一個部門仍警告 | 只建立一筆主管配置 | 對另一個部門另建有效主要主管 |
| 同時存在多位部門主管 | 多筆 `HEAD` 的有效期間重疊 | 保留正確主管或調整生效期間；代理請使用代理主管類型 |
| 同時存在多筆主要任職 | 同一員工有兩筆有效任職設為「主要」 | 只保留一筆主要任職，其他改為兼任 |
| 直屬主管為本人 | 本部門主管或指定主管解析到自己 | 依實際匯報關係改用上層主管、其他指定主管或合法的 `NONE` |

## 10. 維護原則

- 不要用姓名或職稱文字推測誰是最高負責人；以任職的直屬主管來源明確表示。
- 不要為了消除警告而隨意選主管，必須符合實際組織權責。
- 調整主管或組織關係時，同時確認狀態與生效期間。
- 不直接修改資料庫；應使用維護程式保存，以保留驗證與資料一致性。
- 修改後回到「組織人員資料檢查（`FM_PROG002D0007Q`）」重新檢查。
