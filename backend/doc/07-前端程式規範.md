# 07 前端程式規範

## 1. 技術與目錄

沿用既有 Nuxt／Vue／Pinia／QIFU4 元件，不另建第二套 UI framework。

```text
pages/fm_progxxxxxxx/
├─ config.ts
├─ index.vue
├─ create.vue
├─ edit.vue
├─ detail.vue
├─ components/
└─ store/
```

只有實際存在的頁面才註冊 `tb_sys_prog`。

## 2. Query Page

- 使用標準 Toolbar、Grid、GridPagination、QueryPageStore。
- 查詢條件與 page state 可還原。
- 隱藏條件需顯示提示。
- 所有查詢都有分頁、loading、empty、error state。
- 日期依 Tenant timezone 顯示。

## 3. Create／Edit

- 共用 Form component 與 validation schema。
- 前端驗證改善體驗，後端仍是最終驗證。
- immutable 欄位在 Edit 禁止修改。
- 邏輯停用必須二次確認並顯示影響。
- optimistic lock 衝突提示重新載入，不覆蓋他人變更。

## 4. 員工直屬主管

- 選擇主要／兼任部門與該部門職稱。
- 顯示 ORG_HEAD 自動推算出的直屬主管姓名、部門與職稱。
- 授權使用者可選 PARENT_HEAD、EXPLICIT 或最高負責人的 NONE。
- EXPLICIT 選人只列出有效任職，不允許自己；送出前呼叫 manager preview 檢查循環。

## 5. 組織樹

- 樹節點顯示部門名稱、簽核層級、HEAD 與狀態。
- 拖拉只改前端草稿，先呼叫 Preview。
- 有錯誤的節點與原因要明確標示。
- 使用者確認後一次送出 Move Command。
- 禁止逐節點連續呼叫 Update API。
- 支援鍵盤移動或替代操作，不能只有滑鼠拖拉。

## 6. Designer

- BPMN 使用 bpmn-js。
- Form Designer 只產生規格允許的 JSON Schema/UI Schema。
- User Task property panel 以表單設定 Task Policy 與 Resolver，不讓使用者手寫 JSON。
- 發布前顯示 validation report。
- Resolver Preview 顯示每一步部門、層級、主管、代理與略過原因。

## 7. Task Center

- 清楚區分待我處理、受託代理、候選任務與已辦。
- 動作按鈕由 Task Policy 與後端 capability response 決定。
- Reject／Return／Transfer 等理由在前端與後端都驗證。
- 防止 double click；處理中鎖定按鈕。
- 任務已被他人處理時，重新載入並顯示明確訊息。

## 8. API 與安全

- 使用共用 Axios 與 CSRF flow。
- 不從 Cookie 自行解析權限或 Tenant。
- 不把 server error HTML 直接插入 DOM。
- 不把敏感表單資料寫入 localStorage、console 或 analytics。
- 大檔上傳顯示限制、進度與失敗原因。

## 9. 品質

- TypeScript 不使用無理由的 `any`。
- API DTO 有明確型別。
- 共用 Code option 集中管理。
- production build 必須通過。
- 核心表單、樹移動與 Task Action 至少有 component／E2E 測試。
