# 05 安全、權限與稽核

## 1. 身分

- 登入與密碼由 QIFU4 `tb_account` 管理。
- FlowMint 以 `fm_tenant_account` 授權帳號進入 Tenant。
- Employee 是簽核資料，不是登入帳號。
- API 的 initiator、actor 一律由 server-side identity 取得。

## 2. 三種 Role

| 類型 | 保存位置 | 用途 |
|---|---|---|
| 程式權限 | `tb_role` | 頁面、API、按鈕 |
| 組織主管 | `fm_org_unit_head` | 部門簽核人 |
| 簽核群組 | `fm_approval_group*` | 財務、法務等候選人 |

三者不可互相取代。

## 3. 權限命名

每個程式使用：

- `PROGRAM_ID_Q`：查詢。
- `PROGRAM_ID_A`：建立。
- `PROGRAM_ID_E`：修改。
- `PROGRAM_ID_D`：邏輯停用。
- `PROGRAM_ID_X`：發布、樹移動、管理員改派等高風險操作。

Controller 與 UI 都檢查權限；UI 隱藏按鈕不能取代後端授權。

## 4. 資料權限

- 一般使用者：自己的申請與自己的待辦。
- 主管：不因主管身分自動取得所有下屬表單內容，須由流程或報表權限授權。
- 流程管理者：定義及發布，不代表可查看所有表單資料。
- 流程營運管理者：可處理 Incident、改派及終止，但每次操作需理由。
- 系統管理者：管理 Tenant 與帳號範圍。

### 4.1 代起單權限

- 發起人是實際登入並送出表單的帳號，必須由 server-side identity 取得，不接受前端任意指定。
- 申請人是表單所屬人；與發起人不同時，必須通過 `fm_process_start_proxy` 的 Tenant、帳號、流程範圍、狀態與有效期檢查。
- 發起與申請身分必須同時保存於流程及稽核資料，不得因代起單而覆蓋真實操作者。
- 代起單只授權建立申請，不授予查看申請人其他表單、簽核、轉派或代理簽核的權限。
- 簽核代理是不同的授權關係，不得與 `fm_process_start_proxy` 共用或互相推導。

## 5. 稽核

必須記錄：

- 主資料建立、修改、停用與樹移動。
- 表單／流程發布。
- 申請與全部 Task Action。
- 指派解析與重新解析。
- 代理、轉派、管理員改派。
- Incident 處理。

業務操作使用 `fm_task_action` 與快照；管理主資料使用應用程式 audit log。不得把密碼、token 或完整敏感附件內容寫入 log。

## 6. 常見防護

- CSRF：沿用 QIFU4 token。
- XSS：所有 rich text 白名單清理。
- SQL injection：Mapper parameter binding，禁止字串拼 SQL。
- JSON expression：只允許白名單欄位與運算子。
- 附件：副檔名、MIME、大小、SHA-256、病毒掃描介面。
- Rate limit：登入、發起、簽核及管理 API。
- IDOR：每次 load/update 都同時驗證 Tenant 與資料權限。
