# 38 部署環境變數與敏感設定說明

## 1. 目的

本文件定義 FlowMint 後端自訂環境變數、對應的 Spring property、實際使用功能、值格式及輪替影響。
正式環境不得沿用 `application.properties` 內的 fallback 開發值，也不得把 Secret 提交到 Git。

## 2. 設定與程式功能對照

| 環境變數 | Spring property | 使用此設定的程式功能 | 用途 |
|---|---|---|---|
| `JASYPT_ENCRYPTOR_PASSWORD` | `jasypt.encryptor.password` | FlowMint 後端啟動與主資料庫連線；不是單一 FM Program | 解密 properties 中的 `ENC(...)`，目前包含 `db1.datasource.password`。 |
| `FM_DATASOURCE_ENCRYPTION_KEY` | `fm.datasource.encryption-key` | DataSource Pool 管理 `FM_PROG006D0001`；Data Action `FM_PROG006D0002` 執行時也會間接使用 | 以 AES-GCM 加解密 `fm_data_source_pool.PASSWORD_CONTENT` 保存的外部資料庫密碼。 |
| `FM_AI_ENCRYPTION_KEY` | `fm.ai.encryption-key` | AI Provider 管理與簽核解說 `FM_PROG010D0001` | 以 AES-GCM 加解密 AI Provider API Key；載入畫面只回傳遮罩。 |
| `FM_EXTERNAL_API_KEY_PEPPER` | `fm.external-api.key-pepper` | 外部 API Client 管理 `FM_PROG010D0002`、API 說明 `FM_PROG010D0003` 及所有外部 API Key 認證 | 以 HMAC-SHA-256 產生及驗證外部 API Key hash；不是可逆加密 key。 |
| `FM_DATA_ACTION_RATE_LIMIT_PER_MINUTE` | `fm.data-action.rate-limit-per-minute` | Data Action `FM_PROG006D0002` 的 Preview 與正式 Execute API | 個別 Action 未設定限制時，依 `Tenant + Action + 登入帳號` 套用的每分鐘預設呼叫上限。 |

## 3. 格式與預設行為

### 3.1 `JASYPT_ENCRYPTOR_PASSWORD`

- 值為高強度密碼字串，不是 Base64 AES key。
- 後端以此值解開 `db1-config.properties` 內的 `ENC(...)`。
- 未提供時目前會採用 repository 的開發 fallback；正式環境禁止依賴此值。
- 更換後，所有既有 `ENC(...)` 必須以新密碼重新加密，否則後端會因資料庫密碼無法解密而啟動或連線失敗。

### 3.2 `FM_DATASOURCE_ENCRYPTION_KEY` 與 `FM_AI_ENCRYPTION_KEY`

- 必須是 Base64 編碼的 AES key，解碼後長度只能是 16、24 或 32 bytes；正式環境建議 32 bytes。
- 兩者必須分開產生，不得與 JWT、Jasypt 密碼或其他系統共用。
- 應用程式啟動時會驗證格式，空值、非 Base64 或長度不合法會直接失敗。
- 遺失金鑰就無法復原既有密文。直接換 key 也無法讀取舊資料；輪替前必須用舊 key 解密，再以新 key 重加密。

### 3.3 `FM_EXTERNAL_API_KEY_PEPPER`

- 必須是 Base64，解碼後至少 32 bytes（256 bit）。
- Pepper 只參與 HMAC-SHA-256，不保存外部 API Key 明文，也不能由 hash 反推出原 Key。
- 更換 Pepper 後，先前簽發的 Key 將全部驗證失敗；必須規劃停機／過渡期並重新簽發 Client Key。

### 3.4 `FM_DATA_ACTION_RATE_LIMIT_PER_MINUTE`

- 值為正整數，預設 `60`；小於 `1` 時後端採用 `1`。
- 計數涵蓋 Preview 與正式 Execute，並保存於 FlowMint 主資料庫的 Execution Audit，供多節點共享。
- `FM_PROG006D0002` 中個別 Action 的「每分鐘呼叫上限」有值時，會覆蓋這個全域預設。

## 4. 產生 Base64 key／pepper

以下 PowerShell 每執行一次會產生一組獨立的 32-byte 安全亂數 Base64 值：

```powershell
$bytes = New-Object byte[] 32
$rng = [Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)
[Convert]::ToBase64String($bytes)
$rng.Dispose()
```

請分別執行三次，將三個不同輸出配置給：

1. `FM_DATASOURCE_ENCRYPTION_KEY`
2. `FM_AI_ENCRYPTION_KEY`
3. `FM_EXTERNAL_API_KEY_PEPPER`

## 5. Windows PowerShell 配置範例

```powershell
$env:JASYPT_ENCRYPTOR_PASSWORD = "replace-with-strong-secret"
$env:FM_DATASOURCE_ENCRYPTION_KEY = "replace-with-independent-base64-key"
$env:FM_AI_ENCRYPTION_KEY = "replace-with-independent-base64-key"
$env:FM_EXTERNAL_API_KEY_PEPPER = "replace-with-independent-base64-pepper"
$env:FM_DATA_ACTION_RATE_LIMIT_PER_MINUTE = "60"
```

環境變數必須在啟動後端的同一個 process environment 中存在。正式部署應使用 Kubernetes Secret、CI/CD
Secret、作業系統服務帳號的安全設定或企業密碼保管系統，不應依賴開發人員終端機的臨時環境變數。

## 6. 上線與輪替檢查

- 確認三個 Base64 值互不相同，且不等於 repository fallback。
- 確認 Jasypt 密碼可以解開現行 `db1.datasource.password`。
- 先在隔離環境驗證 DataSource Pool 密碼、AI Provider Key 與外部 API Key。
- 備份金鑰及受影響資料；密文資料與金鑰必須成對備份。
- 不可先換 key 再嘗試讀取舊密文。應完成解密、重加密及驗證後才切換正式設定。
- 不得將 Secret、完整 API Key、外部資料庫密碼或解密後內容寫入 log、文件、工單或測試輸出。

## 7. 前後端 CORS：`page.allowedOrigin`

`page.allowedOrigin` 位於 `backend/app/src/main/resources/appConfig.properties`，由後端 `WebConfig` 用於 CORS
allowlist。這不是加密 key，但屬於每個部署環境都必須核對的安全設定。

使用此設定的功能包括登入、Cookie／CSRF 驗證及所有由瀏覽器跨 Origin 呼叫的後端 API，不對應單一 FM
Program。任何前端頁面，包括 Workspace、Form、BPMN、DataSource、AI Provider 與外部 API 管理頁，只要與
後端不同 Origin，都會先受此設定限制。

```properties
page.allowedOrigin=http://127.0.0.1:8077,http://localhost:8077
```

- 值是瀏覽器網址列所使用的前端 Origin，格式為 `scheme://host:port`，不可包含 path。
- `localhost` 與 `127.0.0.1` 不同，`http` 與 `https` 不同，不同 port 也不同。
- 多個值以半形逗號分隔。
- `VITE_API_URL` 是「前端呼叫哪個後端」；`page.allowedOrigin` 是「後端允許哪個前端來源」，不可把 API URL 直接誤當 allowed Origin。
- 後端設定 `allowCredentials(true)`，會攜帶登入 Cookie；正式環境應列出確切 Origin，不得使用廣泛 wildcard。
- 本機開發可修改 `appConfig.properties`；正式環境不得要求每位操作人員在 `java -jar` 後臨時拼接此參數。
- 正式值應由 Windows Service、Docker Compose、Kubernetes Deployment／ConfigMap 或其他部署平台集中配置為環境變數 `PAGE_ALLOWEDORIGIN`，並納入版控、變更審核及部署紀錄。例如部署平台設定值為 `https://flowmint.example.com`，應由服務定義注入，而不是由人員每次手工輸入。
- 若組織採 immutable artifact，同一份 JAR 應部署至各環境，再由各環境的集中配置提供不同 Origin；不應為 DEV、UAT、Production 手工修改並重包不同 JAR。

若由反向代理將前後端發布在相同 Origin，瀏覽器不需要 CORS；反向代理、TLS 終止及外部網址仍須與 Cookie、
CSRF 和前端 API Base URL 一併驗證。
