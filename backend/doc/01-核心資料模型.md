# 01 核心資料模型

## 1. 資料邊界

Tenant 是系統資料隔離範圍。一個 Tenant 可以包含多個公司型組織節點，例如台灣總公司、中國分公司與越南分公司。

```text
Tenant
└─ 組織總根
   ├─ 台灣總公司（COMPANY／Approval Root）
   ├─ 中國分公司（COMPANY／Approval Root）
   └─ 越南分公司（COMPANY／Approval Root）
```


分開 Tenant 作法
```text
Tenant-A
└─ 組織總根
   └─ 台灣總公司（COMPANY／Approval Root）

Tenant-B
└─ 組織總根
   └─ 中國分公司（COMPANY／Approval Root）

Tenant-C
└─ 組織總根
   └─ 越南分公司（COMPANY／Approval Root）
   
```



公司型節點與部門都使用組織單位模型，不建立法人或據點主檔。

## 2. Tenant 與人員

| 資料表 | 用途 |
|---|---|
| `fm_tenant` | 系統組織、預設語系與時區 |
| `fm_tenant_account` | QIFU4 帳號可使用的 Tenant |
| `fm_employee` | 簽核需要的員工基本資料 |

登入帳號以 QIFU4 `tb_account` 為唯一來源。Employee 保存工號、姓名、聯絡資料及有效期間，不保存密碼。

## 3. 組織、職稱與職務

| 資料表 | 用途 |
|---|---|
| `fm_org_unit` | 穩定組織單位 ID 與代碼 |
| `fm_org_unit_version` | 組織名稱、父節點、類型、路徑及有效版本 |
| `fm_org_level_scheme` | 公司型組織適用的簽核職級方案 |
| `fm_org_approval_level` | 一般員工、課長、經理、處長、副總等職級 |
| `fm_org_title` | 某部門可使用的職稱及其簽核職級 |
| `fm_org_duty` | 某部門可使用的簽核、審查或通知職務 |
| `fm_employee_org_assignment` | 員工在部門內的職稱、主要任職及直屬主管 |
| `fm_employee_duty` | 員工在該部門承擔的職務 |
| `fm_org_unit_head` | 部門主要主管、副主管及期間代理主管 |

職稱屬於部門；員工透過部門任職取得職稱。職稱代表位階，職務代表責任，HEAD 代表實際單位主管，三者不可混用。

## 4. 直屬主管

`fm_employee_org_assignment` 保存：

```text
MANAGER_SOURCE
DIRECT_MANAGER_ASSIGNMENT_ID
```

主管來源：

```text
ORG_HEAD      本部門 HEAD
PARENT_HEAD   上層部門 HEAD
EXPLICIT      指定另一筆有效員工任職
NONE          僅最高負責人
```

不得指定自己，不得形成直接或間接主管循環。主管關係依任職有效期間判斷。

## 5. 簽核資源與核決權限

| 資料表 | 用途 |
|---|---|
| `fm_approval_group` | 財務、法務、採購等群組 |
| `fm_approval_group_member` | 群組成員 |
| `fm_workflow_delegation` | 期間代理 |
| `fm_approval_authority` | 表單或流程適用的核決權限 |
| `fm_approval_authority_rule` | 金額、天數、類別等條件及核決終點 |

核決終點可以是簽核職級、部門職稱、部門職務、簽核群組或指定帳號。

## 6. 流程定義與執行

| 資料表 | 用途 |
|---|---|
| `fm_process_def` | 流程穩定主檔 |
| `fm_process_version` | BPMN XML 版本 |
| `fm_process_start_policy` | 流程可發起者 |
| `fm_task_policy` | User Task 可執行動作與政策 |
| `fm_task_assignment_rule` | 簽核人 Resolver |
| `fm_process_instance` | Flowable instance 業務索引 |
| `fm_task_assignment_snapshot` | 指派解析表頭 |
| `fm_task_assignment_snapshot_dtl` | 指派人員、職稱、職級與解析路徑 |
| `fm_assignment_incident` | 找不到簽核人或解析錯誤 |

## 7. 表單與稽核

| 資料表 | 用途 |
|---|---|
| `fm_form_def` | 表單穩定主檔 |
| `fm_form_version` | JSON Schema、UI Schema 與發布版本 |
| `fm_form_data` | 使用者目前填寫內容 |
| `fm_form_snapshot` | 每次流程動作的不可變表單快照 |
| `fm_task_form_rule` | 各關卡欄位 Hidden／Read／Edit |
| `fm_attachment` | 表單附件中繼資料 |
| `fm_task_action` | 送出及全部簽核操作軌跡 |
| `fm_notification` | 站內與 Email 通知 |

## 8. 外部系統邊界

- `tb_account`：登入身分。
- `tb_role`、`tb_user_role`：程式與 API 權限。
- `tb_sys_prog`：頁面與功能註冊。
- Flowable `ACT_*`：流程引擎資料，由 Flowable 管理。

FlowMint 不建立第二套密碼，不直接更新 Flowable runtime table，不把程式權限 Role 當成組織主管或簽核群組。
