# FlowMint 新系統總綱

版本：2.0  
日期：2026-07-30  
狀態：全系統重新規劃基準

## 1. 產品定義

FlowMint 是可供台灣與中國大陸企業使用的簽核系統，負責：

- 建立簽核所需的最小人員與部門資料。
- 設計表單與 BPMN 流程。
- 依部門、主管、簽核層級、群組及表單條件找出簽核人。
- 處理申請、待辦、同意、駁回、退回、撤回、轉派、代理及加簽。
- 保存不可否認的表單快照、指派快照與操作軌跡。
- 提供流程監控、指派異常及管理員處理。

FlowMint 不是 HR、ERP、集團治理、法人主檔、廠區或據點管理系統。

## 2. 唯一核心關係

```text
Tenant
  ├─ Account / Employee
  ├─ Approval Level Scheme
  ├─ Department Tree
  │   ├─ Employee Membership
  │   └─ HEAD / DEPUTY_HEAD / ACTING_HEAD
  ├─ Approval Group
  ├─ Form Definition
  └─ Process Definition
      └─ Task Policy + Assignment Rule
          └─ Process Instance / Task / Audit Snapshot
```

Tenant 是唯一資料隔離邊界。「總公司」是部門樹根節點，不是法人資料。

## 3. 明確刪除的概念

新系統不建立以下 FlowMint 主資料：

- Enterprise Group／集團。
- Legal Entity／法人公司。
- Location／據點、廠區、地址及座標。
- Employment、Job Family、Job。
- Grade Scheme、Grade。
- Position、Position Version、Headcount。
- Project Organization。
- Work Queue。
- Org Service Scope。

如果未來真的有需求，必須以獨立需求重新評估，不預留空表、不增加外鍵、不讓核心 Resolver 依賴。

## 4. 設計原則

1. 簽核人必須可解釋：每次解析都能說明從哪個部門、層級及主管得到結果。
2. 簽核人不得寫死在 BPMN XML。
3. 樹深、部門類型及簽核層級是三種不同概念。
4. 找不到簽核人不得無聲通過。
5. 歷史流程不受日後組織異動污染。
6. 帳號身分來自登入狀態，不接受 Request Body 冒用。
7. 所有資料查詢與異動都必須限制 Tenant。
8. 台灣與中國大陸共用模型，以 Locale 與可維護名稱處理差異。
9. 先完成最小垂直切片，再增加非核心能力。
10. 文件、DDL、程式及測試使用同一份代碼表與狀態定義。

## 5. 正式文件效力

`newdoc` 是新版本的唯一規劃依據。舊 `doc` 只用於理解現況與遷移，不得再作為新功能設計依據。正式實作順序為：

```text
newdoc 規格
  → flowmint-core-schema.sql
  → Entity / Mapper / Service / Logic
  → API / UI
  → Test / Deployment
```
