# 10 測試與驗收

## 1. 測試層級

| 層級 | 範圍 |
|---|---|
| Unit | 樹、層級、狀態機、Resolver、表單驗證 |
| Mapper | Tenant 條件、分頁、索引使用、optimistic update |
| Integration | MariaDB constraint、Transaction、Flowable |
| API | Identity、Permission、Validation、HTTP status |
| Frontend | Form、Tree、Designer、Task action |
| E2E | 建組織到完成簽核 |

## 2. 必測安全案例

- Request body 冒用 initiator／actor。
- 讀取或更新其他 Tenant ID。
- 沒有權限直接呼叫 API。
- 重複 Submit／Approve。
- 已完成 Task 再操作。
- JSON expression injection。
- 附件類型、大小與路徑攻擊。

## 3. 組織案例

- 根部門建立。
- 同 Tenant 唯一部門代碼。
- 父子循環。
- 父層級低於子層級。
- 允許跳級。
- 子樹拖拉、排序、整批回滾。
- stale version。
- 同時兩位 HEAD 重疊。
- 部門職稱對應不存在或停用的 Level。
- 員工任職引用其他部門的職稱。
- 同一部門職務多人擔任時的模式與優先順序。
- 金額／天數核決條件邊界與重疊。
- Employee 同時兩個主要部門。
- ORG_HEAD 自動帶入直屬主管。
- 部門 HEAD 使用 PARENT_HEAD。
- EXPLICIT 指定主管必須是有效任職。
- 主管不得是自己，也不得形成兩人或多層循環。
- 主管任職失效後新解析建立 Incident，歷史 Snapshot 不變。
- 組織異動不改變舊快照。

## 4. Resolver 案例

- 本部門主管。
- 父部門主管。
- 下一個較高層級。
- 目標層級。
- 逐級簽到指定層級。
- 根部門主管。
- Acting、Deputy、Workflow Delegation。
- 自簽四種政策。
- 重複三種政策。
- 找不到人建立 Incident。
- Preview 與 Runtime 完全一致。

## 5. 台灣／中國大陸案例

- `zh-TW` 顯示處、部、課、組。
- `zh-CN` 顯示事业部、部门、科室、组。
- 同一 Resolver Code 在兩種名稱下結果一致。
- Tenant timezone 的顯示與有效日判斷正確。
- UTF-8 可保存繁體、簡體及罕見姓名字元。

## 6. 第一個端到端驗收

```text
00001 總公司（HEAD=總經理）
  ├─ 10000 製造處（HEAD=製造處長）
  │   ├─ 11000 生產部（HEAD=生產經理）
  │   │   └─ 11100 生產課（HEAD=課長）
  │   └─ 12000 品保部（HEAD=品保經理）
  └─ 20000 管理處
      ├─ 21000 人力資源部
      └─ 22000 財務部
```

生產課員工發起請假或費用申請，系統依流程規則找到課長、經理、處長或總經理，保存每次表單與指派快照，最後完成或駁回。
