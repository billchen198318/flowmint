## 強制開發原則

- FlowMint 前後端程式必須以 `C:\home\qifu4` 現有程式為實作範本。
- 開發前必須閱讀 `15-QIFU4前端實作規範.md`、`16-QIFU4後端持久層規範.md`、`17-QIFU4帳號與Role邊界.md`。
- 不得自行發明查詢、Grid、Toolbar、toast、欄位驗證、Controller 結果封裝或持久層流程。
- Query／Create／Edit 頁面應先選定相近的 QIFU4 範例，再替換為 FlowMint 業務欄位。
- 後端分頁查詢必須使用 QIFU4 的 `setQueryResponseJsonResult(...)` 封裝回應。
- 表單驗證失敗時，前端必須同時套用後端 `checkFields`，並以 `toast.warning(escapeQifuHtmlMsg(response.data.message))` 顯示訊息。

## 2026-07-30 問題修正紀錄

### 必填欄位只有紅框、沒有 toast

原因：前端曾自行加入驗證並提前中止，未依 QIFU4 使用後端回傳訊息。  
修正：Create／Edit 儲存改為接收 `response.data.checkFields`，失敗時呼叫：

```ts
checkFields.value = response.data?.checkFields || {};
toast.warning(escapeQifuHtmlMsg(response.data.message));
```

### SQL 查到資料但 Grid 沒有顯示

後端 log 已確認：

- `fm_tenant` count 為 `1`
- 分頁 SQL 確實查到 Tenant `A01`
- HTTP 回應為 `200 OK`

真正原因：`FMPROG001D0001Controller.findPage()` 手動複製 Service 的 `QueryResult`。Service 內部結果的 `success` 預設為 `N`，造成前端進入失敗分支並保持空 Grid。

已改為 QIFU4 標準結果封裝：

```java
this.setQueryResponseJsonResult(viewResult, result, searchBody.getPageOf());
```

同時前端查詢頁已補上：

- 按「查詢」先回第 1 頁。
- 查詢前清空舊列表。
- QIFU4 成功旗標判斷。
- 空回應、查詢錯誤與分頁總筆數處理。
